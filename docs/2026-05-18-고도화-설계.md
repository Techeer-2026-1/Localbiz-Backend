## 1. 검색 파이프라인 최적화

### 문제
`name ILIKE '%홍대%'`로 장소명 매칭 → "홍대쌀국수(영등포)", "홍대빽바지(노원)" 등 노이즈 발생.
OS k-NN도 district 필터 없이 임베딩 유사도만으로 선정.

### 데이터 근거
- 총 535,432개 장소, 19 카테고리, 25 자치구
- "홍대" 이름 매칭 중 마포구 아닌 것: 20건+ (브랜드명으로 "홍대" 사용)
- 마포구+쇼핑 필터만으로도 5,110개 — 충분한 후보 풀

### 해결

**공유 유틸 `src/utils/geo_mapping.py` (신규)**
- `NEIGHBORHOOD_TO_DISTRICT` 매핑 테이블 (30+ 엔트리)
- PR #101의 course_plan_node 매핑을 공유 유틸로 추출
- "홍대"→마포구, "강남역"→강남구, "이태원"→용산구 등

**변경 파일:**
- `query_preprocessor_node.py` — Gemini JSON 응답에 neighborhood/district 추출 추가
- `place_search_node.py` — PG: district+category 필터 우선, name ILIKE 보조. OS: bool+filter에 district 추가
- `place_recommend_node.py` — 동일 district 필터
- `course_plan_node.py` — PR #101의 매핑을 공유 유틸로 추출

**검색 우선순위 변경:**
```
변경 전: name ILIKE → OS k-NN(필터 없음) → 병합
변경 후: district+category 필터(PG) → district+category(OS k-NN) → name ILIKE 보조 → 병합
```

**테스트 쿼리:**
- "홍대 쇼핑 코스 짜줘" → 마포구 쇼핑 장소만
- "강남 카페 추천해줘" → 강남구 카페만
- "이태원 맛집" → 용산구 음식점만

## 2. 이미지 포함 응답

### 문제
PlaceBlock에 `image_url` 필드 존재하지만 항상 null.

### 해결

**`src/utils/naver_blog.py` (신규)**
- 네이버 블로그 검색 API → 썸네일 URL 추출
- 타임아웃 2초, 실패 시 None (graceful degradation)

**변경 파일:**
- `place_search_node.py` / `place_recommend_node.py` / `course_plan_node.py`
  - 블록 생성 시 `fetch_blog_image()` 호출 (asyncio.gather 병렬)

**퀄리티 게이트:**
- `ENABLE_BLOG_IMAGES=true/false` 환경변수 토글
- 테스트 후 퀄리티 낮으면 false로 폐기

**테스트 쿼리:**
- "홍대 맛집 추천해줘" → 각 장소 카드에 이미지 포함 여부 + 퀄리티 육안 판단
